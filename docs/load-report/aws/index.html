O que esta evidência permite afirmar

Os gates de cada execução admitida passaram e o verificador salvo reconciliou os efeitos financeiros com o ledger. O relatório lê agregados; não consulta PostgreSQL nem reconstrói o ledger novamente. Não há comparação quantitativa local × AWS: fontes, instrumentos, recursos e janelas são diferentes.

Esta campanha possui uma única amostra AWS. Não existem três FULL AWS aprovados para medir variação. A alteração operacional do health check do ALB para /health/live precedeu esta rodada e não integra a identidade do bundle de aplicação; nenhuma melhora causal de performance é inferida.

Limites e reprodução offline

Os gráficos não contêm CPU, memória consumida, I/O do RDS, ALB, custo ou latência por evento: essas métricas não pertencem aos agregados admitidos. Percentis por fase não são um percentil global da campanha. Métricas ausentes aparecem como UNKNOWN ou lacunas; nunca viram zero.

Uma rodada aprovada demonstra esta execução e estes invariantes. O relatório não transforma retries de SQS em perda de comandos nem usa a ausência de erros HTTP para afirmar ausência de throttling interno.

campaign.json é uma projeção fechada, versionada, com contagens, quantis, séries anônimas e impressões dos arquivos de origem. Não contém fixture, payload financeiro, ARN, endpoint, credencial ou identificação de réplica. Ela permite recriar este HTML sem os caches privados e sem iniciar serviços.

BUN_CONFIG_NO_ENV_FILE=true BUN_CONFIG_NO_AUTO_INSTALL=true bun --no-env-file scripts/render-load-report.ts   --campaign-data docs/load-report/aws/campaign.json   --output-dir /tmp/novo-relatorio-aws

O destino precisa ser novo. Para recalcular a projeção a partir dos agregados originais, use --campaign aws, um ou mais --run DIR e --output-dir NOVO_DIR. Somente os nomes literais permitidos são abertos. Fontes diferentes, FULL parcial, gate financeiro falho ou prova remota incompleta são recusados antes da escrita.
